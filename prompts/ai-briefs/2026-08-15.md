# 2026-08-15 AI판 지정 편집 브리프

## 주제와 중심 질문

2026년 8월 13일 공개된 프리프린트 `A Programming Paradigm for Spatiotemporal
Composability`와 그 구현인 Cordis를 다룬다. DeepSeek Harness가 Cordis를 기반으로
삼았다는 사실을 출발점으로, 플러그인 구조가 AI의 소프트웨어 유지보수와 개선에 어떤
이점을 줄 수 있는지 설명한다.

중심 질문은 다음과 같다.

> 앱을 처음부터 작은 플러그인, 명시적인 의존성, 되돌릴 수 있는 변경으로 구성하면 AI가
> 더 좁은 범위를 이해하고 시험하고 교체하며 실패 시 복구할 수 있는가?

중심 결론은 `가능성을 높이는 구조적 이점은 있지만 Cordis 자체가 자기개선 엔진은
아니다`로 제한한다. 이 주제는 당일 다른 후보보다 우선하되, 지정됐다는 이유로 선정 점수나
근거 기준을 낮추지 않는다. 논문·코드·공식 Harness 문서로 중심 주장을 지탱하지 못하면
추측으로 메우지 말고 `no-publish`한다.

## 제목과 도입부

제목은 뉴스형으로 쓴다. 다음 방향을 우선 검토한다.

> DeepSeek·베이징대 연구진, 실행 중 앱 부품을 바꾸는 ‘Cordis’ 설계 공개

원문이 직접 지지하지 않는다면 `AI가 스스로 진화하는 앱을 완성했다`처럼 쓰지 않는다.
제목에 `하지만`, 근거 등급, 동료평가 여부, 면책 문구를 모두 넣지 말고, 프리프린트라는
상태와 검증 한계는 summary와 본문에서 분명히 밝힌다.

첫 세 문단은 다음 순서로 쓴다.

1. 누가 무엇을 공개했는가.
2. 실행 중 플러그인을 교체한다는 것이 왜 AI 유지보수와 연결되는가.
3. 지금 확인된 것은 설계·형식 모델·구현·기존 적용 사례이며, 자율 자기개선 자체는 아직
   검증되지 않았다는 경계.

## 독자가 이해해야 할 구조

- Cordis를 단순한 `플러그인 안의 플러그인`으로 설명하지 않는다. **소유권과 정리 범위를
  나타내는 Context 트리**, **서비스 제공자와 소비자를 잇는 의존성 그래프**, **컴포넌트
  생명주기**, **효과의 역순 회수**가 겹친 구조라고 설명한다.
- `spatiotemporal`은 물리적 시공간이 아니다. temporal composability는 부품을 제거할 때
  그 부품이 만든 변경을 안전하게 회수하는 능력이고, spatial composability는 필요한
  서비스가 생기거나 사라질 때 의존 부품을 재조정하는 능력이라고 쉬운 한국어로 푼다.
- `effect`는 컴포넌트가 환경에 만든 변경, `coeffect`는 컴포넌트가 환경에서 요구하는
  서비스·조건이라는 구체적인 장면을 먼저 보여 준 뒤 용어를 붙인다.
- 다층 구조라는 표현은 사용할 수 있지만, 고정된 계층형 레이어만 있는 것처럼 쓰지 않는다.
  부모·자식 Context의 트리와 가지를 가로지르는 의존성 그래프를 구분한다.
- LLM의 다음 토큰 생성 방식인 `자기회귀`, 컴포넌트가 하위 컴포넌트를 만드는 `재귀적
  구성`, 에이전트가 자신의 도구를 바꾸는 `자기변형·자기진화`를 혼동하지 않는다.

## AI 유지보수 관점에서 분석할 것

- AI가 거대한 앱 전체가 아니라 한 플러그인과 명시된 계약에 집중할 수 있다는 점.
- 의존성 그래프로 변경 영향 범위를 추정하고, 같은 인터페이스의 기존·신규 구현을 비교
  시험하며, 실패한 변경의 폭발 반경을 줄일 가능성.
- context를 거쳐 등록한 listener, resource, service 등을 역순으로 회수할 수 있어 동적
  교체와 rollback의 기반이 된다는 점.
- 현재 플러그인 트리, 제공 서비스, 의존 관계, lifecycle 상태를 구조화해 AI가 관찰할 수
  있다면 자연어 문서만 읽을 때보다 유지보수 판단이 쉬워질 가능성.
- 안전한 자기개선을 위해서는 작은 안정 코어와 교체 가능한 외곽을 분리해야 한다는 설계
  판단. 권한, sandbox, 감사 기록, 검증, rollback은 AI가 자유롭게 교체하는 플러그인보다
  강한 변경 게이트 아래 두는 편이 적절하다.

Cordis가 개선안을 선택하는 목적함수, 회고, 학습, benchmark, 승인 정책을 제공하는 것처럼
쓰지 않는다. Cordis는 자기개선 엔진이 아니라 변경을 더 작고 관찰 가능하며 회수 가능하게
만드는 실행 토대라는 선을 지킨다.

## 논문과 구현의 근거 한계

한계는 한 절에서 명확하게 설명하고 다른 절에서 같은 경고를 반복하지 않는다.

- 논문은 2026년 8월 13일자 active-revision preprint다. 현재 공개 상태에서 arXiv, DOI,
  학회 게재나 동료평가 여부를 다시 확인한다.
- 형식 모델은 preservation, recovery exactness, dependency ordering, progress,
  confluence 등을 다루지만, 역함수가 실제 원상복구한다는 의무와 독립성·비순환성 같은
  전제를 함께 설명한다. 정리 이름을 길게 나열하는 대신 보장 범위와 조건을 쉬운 말로
  요약한다.
- runtime은 컴포넌트 작성자가 제공한 inverse가 올바른지 자동 증명하지 않는다.
- context 경계 밖으로 이미 보낸 network message, 결제, 외부 공유 파일 같은 emission은
  자동 rollback 대상이 아니다.
- 언어 수준의 dependency mediation은 악성 코드를 격리하는 sandbox가 아니며 별도의 실행
  경계가 필요하다.
- 사례 연구 Koishi는 4,000개 이상 커뮤니티 플러그인의 존재·채택 사례지만 단일 TypeScript
  생태계의 관찰 연구다. 대조 실험, runtime overhead, 개발 생산성 비교가 없고 Koishi는
  논문의 Cordis v4가 아니라 v3를 사용한다.
- 논문 결론도 self-evolving agent harness에서의 검증을 미래 연구로 둔다. DeepSeek
  Harness가 Cordis를 채택했다는 것과 자율 자기개선의 효과가 검증됐다는 것을 분리한다.

## 문체와 구성

전문성과 깊이는 유지하되 논문 심사표처럼 쓰지 않는다. 구체적인 사용 장면을 먼저 보여
주고 기술 개념을 뒤에 붙인다. 본문은 다음 흐름을 권장한다.

`무엇이 공개됐나 → Cordis 구조를 한 장면으로 이해하기 → AI 유지보수에 주는 이점 →
보장되는 것과 보장되지 않는 것 → 어떤 앱 설계에 적용할 수 있나`

`확인할 수 없다`, `독립 검증이 아니다`, `결론 내릴 수 없다`는 문장을 여러 절에서
반복하지 않는다. 핵심 한계는 한 번 분명히 설명하고, 근거 등급·재현성·이해상충의 상세는
근거 원장에 둔다. 깊이는 전문 용어의 수가 아니라 구조와 trade-off를 이해시키는 데서
나오게 한다.
