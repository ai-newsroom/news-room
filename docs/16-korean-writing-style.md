# 한국어 기사 문체 공통 계약

> 계약 ID: `korean-writing-baseline-v1`
>
> 적용 범위: AI판과 EDA판을 비롯해 자동으로 작성하는 모든 설명형 기사. 이 문서는
> 판별 취재 기준이나 기사 구조를 정하지 않는다. 어떤 기사든 먼저 갖춰야 할 자연스러운
> 한국어 문장의 바닥만 정한다.

## 1. 문장부터 자연스러워야 한다

정확한 정보도 독자가 문장을 다시 해석해야 한다면 제대로 전달되지 않는다. 영문 자료를
읽고 쓴 기사라도 영문의 어순, 명사 결합, 은유를 그대로 옮기지 않는다. 원문 표현보다
한국어에서 실제로 쓰는 말과 문장 순서를 우선한다.

- 주어와 서술어를 가깝게 두고, 한 문장에는 중심 생각 하나를 담는다.
- 명사를 연달아 붙이기보다 누가 무엇을 하는지 동사로 쓴다.
- `~을 통해`, `~에 기반해`, `~의 관점에서`, `~에 위치한다`처럼 없어도 뜻이 같은
  연결 표현은 덜어 낸다.
- 영어의 추상적인 비유를 새 한국어 표현처럼 만들지 않는다. `결론의 천장`, `구현 표면`,
  `운영 경계에서 갈린다`처럼 독자가 뜻을 다시 풀어야 하는 표현은 사실을 직접 쓴다.
- 정확성을 해치지 않는 범위에서 일상적인 낱말을 먼저 쓴다. 전문 용어가 필요하면 처음
  나올 때 짧게 풀고, 이후에는 같은 이름을 일관되게 사용한다.
- 앞 문장을 명사만 바꾸어 반복하지 않는다. 같은 주의사항은 가장 필요한 곳에서 한 번
  분명히 설명한다.
- 짧게 압축하느라 인과관계를 생략하지 않는다. 어려움과 길이 중에서는 필요한 설명을
  더하는 쪽을 택한다.

## 2. 소제목은 독자가 바로 이해할 수 있게 쓴다

소제목은 보고서의 분류표나 작성자의 판정문이 아니다. 해당 절이 답할 질문이나 새로
알려 줄 사실을 평범한 한국어로 보여 준다.

- 소제목만 읽어도 그 절에서 무엇을 알게 되는지 짐작할 수 있어야 한다.
- 추상명사 두세 개를 이어 붙이거나 낯선 비유로 의미를 압축하지 않는다.
- `구조`, `결과`, `기술적 의의`처럼 범위가 넓은 한 단어보다 구체적인 내용을 쓴다.
- 모든 소제목을 같은 문형으로 맞추지 않는다. 질문, 사실, 짧은 설명 가운데 내용에 가장
  자연스러운 형식을 고른다.
- 본문을 읽어야만 해석되는 멋진 문장보다 바로 이해되는 문장을 택한다.

예를 들어 `RAG의 병목은 첫 검색 결과에 갇히는 데 있었습니다`보다는
`기존 RAG는 첫 검색 결과만 보고 답했습니다`가 직접적이다.
`벤치마크 수치는 방향을 보여 주지만 결론의 천장은 낮춥니다`보다는
`성능은 좋아졌지만 실제 환경 검증은 남았습니다`가 뜻을 바로 전한다.

## 3. 기술 용어와 영어를 다루는 법

영어를 모두 번역하는 것이 목표는 아니다. API, SDK, RTL처럼 독자가 실제 업무에서 쓰는
이름은 유지할 수 있다. 다만 영어를 한국어 문장의 뼈대로 사용하지 않는다.

- 제품명, 명령어, 코드 식별자와 업계에서 굳어진 용어는 원문을 유지한다.
- 낯선 용어는 처음 등장할 때 한국어 뜻과 이 글에서 하는 일을 함께 설명한다.
- 한 문장에 영어 명사를 여러 개 나열해야 한다면 문장을 나누거나 단계별로 설명한다.
- 원문의 수동태와 명사형을 그대로 옮기지 말고 한국어에서 자연스러운 주체와 동사를 찾는다.
- 영어 단어를 한글 조사로 이어 붙인 문장이 길어지면, 먼저 쉬운 설명을 쓰고 정확한 이름을
  다음 문장에 둔다.

## 4. 마지막 한국어 편집

초고 작성과 한국어 문장 편집은 별도 작업으로 수행한다. 한국어 편집자는 새로운 취재를
하거나 결론을 바꾸지 않는다. 제목, 요약, 소제목과 설명 본문을 다음 순서로 읽는다.

1. 번역투, 추상적인 조어, 불필요한 명사형을 찾는다.
2. 길고 복잡한 문장을 나누고 주어와 서술어를 바로 세운다.
3. 전문 용어가 나오기 전에 독자가 붙잡을 구체적인 장면이나 쉬운 설명이 있는지 본다.
4. 소제목만 따로 읽어도 자연스럽고 구체적인지 확인한다.
5. 소리 내어 읽었을 때 한국어 화자가 실제로 설명할 법한 문장인지 확인한다.

이 과정에서 사실, 중심 주장, 수치, 단위, URL, 제품·버전·commit, 코드 식별자, 근거 등급,
재현성, benchmark 조건, 한계, 이해상충과 근거 부록을 바꾸지 않는다. 자연스럽게 고칠 수
없는 문장이 사실 변경을 요구한다면 임의로 손대지 않고 검증 단계로 돌려보낸다.
