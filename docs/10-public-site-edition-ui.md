# 공개 사이트 edition UI 계획

> 상태: 시사·AI·EDA 공개 반영 완료 (2026-08-13)
>
> 범위: 시사판, AI판, EDA판의 공개 정보 구조와 공통 UI. 판별 콘텐츠 수집·판정 계약은 분리한다.

## 1. 문제

기존 사이트의 공통 헤더는 시사판의 `기사`와 `편집국`만 전역 메뉴처럼 표시한다.
AI판은 본문 안에 `AI News / 시사판` 메뉴를 다시 만들어 판 전환과 판 내부 이동을 섞고,
AI 화면의 footer도 시사판의 토론·프롬프트 공개 방식을 AI판 전체의 방식처럼 설명한다.

이 구조에서는 독자가 다음을 구분하기 어렵다.

- `news-room`이 시사판의 이름인지 여러 판을 아우르는 이름인지
- AI판과 시사판의 편집 방식이 같은지 다른지
- 다른 판으로 이동하려면 어느 메뉴를 사용해야 하는지

## 2. 결정

`news-room`을 상위 브랜드로 두고 `시사판 / AI판 / EDA판`을 독립 edition으로 표시한다.
판 전환은 모든 화면의 공통 헤더 한 곳에서만 제공한다. 판 내부의 기사 목록과 편집 정보는
본문에서 문맥에 맞는 링크로 제공한다.

EDA판은 2026-08-13 사용자의 명시적 출시 요청 뒤 공개 정보 구조에 포함했다. 첫 기사는
사람 승인 release를 사용했고, 이후 별도 승인된 `eda-auto-publish-v1` release도 같은
artifact hash·route 검사를 통과한 경우에만 공개한다.

공통 구조는 공유하지만 판의 편집 계약을 UI에서도 섞지 않는다.

| 판 | 대표 주소 | 공개 설명 | 투명성 정보 |
|---|---|---|---|
| 시사 | `/`와 `/news/<id>/` | 하루의 시사 이슈 하나를 토론으로 깊이 읽음 | 편집 강령, 역할 프롬프트, 소스, 기사별 토론 |
| AI | `/ai/`와 `/ai/<id>/` | 모델·평가·시스템 변화를 원문과 재현 범위로 검증 | 공개 승인, 근거 수준, 재현성, 원문·버전 |
| EDA | `/eda/`와 `/eda/<id>/` | 도구·표준·학회·논문의 변화를 설계 흐름 영향과 조건으로 검증 | 사람 공개 승인, 근거 수준, 재현성, 벤더 주장과 미확인 범위 |

기존 시사 기사 URL과 AI 기사 URL은 바꾸지 않는다.

## 3. 공통 시각 체계

- masthead, 본문 폭, 타이포그래피, 간격, focus 상태는 세 판이 공유한다.
- 시사판은 적갈색, AI판은 청색, EDA판은 올리브색 accent를 사용한다.
- 색상만으로 현재 판을 알리지 않고 header의 `aria-current`, 판 이름, 페이지 제목을 함께 쓴다.
- 판 소개는 kicker, 제목, 한 문단 설명의 동일한 위계로 표시한다.
- AI의 검증 수준은 긴 내부 상태 문장 대신 짧은 공개 승인·근거 수준·재현성 항목으로 나눈다.
- 모바일에서도 판 전환 세 항목을 한 줄에 유지하고, 브랜드와 설명만 세로로 배치한다.

## 4. 구현 순서와 완료 조건

1. 공통 layout이 edition을 입력받아 판 전환, accent, 판별 footer를 렌더링한다.
2. 시사·AI·EDA landing이 같은 hero와 feed 위계를 사용한다.
3. 시사·AI·EDA 기사에서 중복 판 내비게이션을 제거하고 공통 header에 연결한다.
4. 시사판 편집국 페이지가 자기 적용 범위를 시사판으로 한정한다.
5. 정적 build, 기존 기사 URL, 승인된 AI·EDA route, 세 판 내비게이션과 모바일 화면을 검증한다.

## 5. 비범위와 되돌림

이 UI의 최초 변경은 콘텐츠 원문, release 승인, collection 경계, runner, schedule,
git·배포 정책을 바꾸지 않았다. 이후 AI판은 `ai-auto-publish-v1` authorization도
사람 승인과 같은 hash·route 검사를 통과한 경우에만 표시하도록 확장됐다. 통합 feed는
만들지 않는다. EDA판도 별도 collection·route와 별도 자동 출고 policy를 사용한다.

공개 반영은 로컬 검증 뒤 별도 commit·push·deploy 단계로 진행한다.

## 6. 검증 기록

- 2026-07-26 `origin/main`의 시사 기사(7월 26일까지)를 포함한 격리 작업 공간에서 검증
- `npm test`: edition navigation, 기존 AI release route, provenance 격리 fixture 통과
- 정적 build: 기존 시사·AI route 유지
- 데스크톱 1280×800: 시사·AI landing의 단일 판 전환과 active 표시 확인
- 모바일 390×844: 두 landing, 최신 시사 기사, AI 기사, 편집국의 공통 header 확인
- 모든 모바일 확인 route에서 문서 가로 overflow 0
- AI 근거 원장 표: 문서 폭은 유지하고 표 내부에서만 가로 scroll 허용

## 7. 공개 반영 뒤 평가할 다음 inbox 후보

현재 UI 변경과 같은 파일을 동시에 수정하지 않도록 아래 항목은 이 변경의 공개 반영 뒤에
우선순위를 평가한다.

1. AI의 `E1~E4`, `R0~R3`가 무엇을 뜻하는지 독자가 확인할 수 있는 기술판 검증 기준
   페이지를 만들고 기사 metadata에서 연결한다.
2. 시사판 기사 수가 계속 늘어날 때 첫 화면의 길이를 제한할 archive 또는 정적 pagination을
   도입하되 기존 `/news/<id>/` URL과 최신 기사 발견성을 보존한다.
